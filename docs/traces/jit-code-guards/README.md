# Original-seed opcode guard census

This is a diagnostic count under runtime603679 and original seedd9c661, not an optimization or a timing benchmark. `census.json` records exact hashes, all512 original/instrumented WAT body hashes, original-input admission equality, complete raw100M interpreter/original/instrumented snapshots, counters and the bounded block-length/entry-offset histogram.

`census.mjs` is the exact run source. From the repo root with a built web runtime, pinned WABT dependency and the original fixed MBX snapshot available, run `node docs/traces/jit-code-guards/census.mjs`. It writes into `.context/jit-code-guards`; create that directory first. The raw fixture is the existing ignored `.context/graphics-speed/fixed-dismiss.snap`, SHA764486ea35ba9832f35c8118397f361026ed21119295321e0a29519509de1244. It is not bundled again here. Future rebuilt modules or inputs will be separately fingerprinted and are not automatically the same historical run.

All inserted counter expressions are enclosed by WAT comment markers. Removing those markers and expressions must reproduce each original generated body byte-for-byte; the script asserts this for every region before running. Counters use2176 separately allocated host bytes outside serialized machine state. Every original opcode guard and its order remains intact. Counter overhead makes run duration unsuitable for performance comparison.

Result:92,847,493 attempted opcode checks,11,201,176 for instructions before the block's actual entry (12.064%). There are74,572,089 instruction-body starts and73,093,840 retirements, so checks/retirement is1.27025 and checks/body-start1.24507. These are execution-weighted counts. Static unweighted block layout was much more pessimistic and must not be used as an actual work estimate.

All three full raw snapshots equal d4ca9be92fc97409eef7e93545c4ac1cb2963eacb079a405181840ea6a41e38c; original and diagnostic generated/call/region counters match exactly. Three stale-code checks stop early. Histogram capacities and observed attempts reconcile, including these early exits. No raw guard is moved, skipped or relaxed. The proposed later policy's different stale-code behavior would need its own architectural tests and separate timing evidence.
