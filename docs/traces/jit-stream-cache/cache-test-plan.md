## Required evidence

All first/stable Settings/Home screenshots must pass the existing frozen-baseline RGB tolerance and manual genuine-UI review; retain mismatches without widening the threshold. Emulator generated retirement must be positive, initial guest identity equal, normal state restore/lifecycle successful, and no page/worker error permitted. Native cache evidence needs the exact seed URL and complete trace: `v8.wasm.cachedModule` signals serialization before asynchronous persistence; `v8.wasm.moduleCacheHit` signals metadata retrieval before digest validation/deserialization. Neither event alone proves durable accepted native code. Look for the paired digest/deserialize path and successful V8 deserialization event, with no `moduleCacheInvalid`/`moduleCacheInvalidDigest`, and verify its source/binding. If trace lacks an unambiguous accepted-deserialization receipt, retain uncertainty and inspect exact source/event linkage before claiming reuse. Mere reduced compilation, low network bytes,304 or disk-cache hit is insufficient.

A positive mechanism gate can justify a later quiet **return-visit** browser ABBA with independent baseline/candidate persistent profiles, equivalent cache-training workload and uncut recordings. First-ever launch and guest-warm revisits are distinct measurements. A production proposal additionally needs real service-worker CacheStorage/offline update validation; the initial bypassed-SW gate cannot establish that behavior.

Record all events and trace completeness so this inference remains reviewable.
