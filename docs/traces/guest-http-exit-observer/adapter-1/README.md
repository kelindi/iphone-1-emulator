## Observations and focused proof

`adapter.c` records only actual pre-instruction events. Its hook always returns false. It resolves current owner from the actual CurrentThread global through thread/task/proc fields using the RAM-only, copied-CPU walker; it never mistakes USR r9 for the kernel thread. The first executed own BLX establishes owner identity and records the complete CP15 words. Subsequent address-space admission binds SCTLR, TTBR0/1, TTBCR, DACR, FCSE and context ID. Host observer configuration is the only intentional machine-side change.

Six own callsites are paired with their live eager import slot, BLX register, relocated original code, ARM/Thumb mode, LR, SVC entry, original syscall return, and own return: exit, listener poll, accept, client close, setsockopt, and console write. On paths where the real daemon actually calls `___error`, the observer also pairs its real Thumb entry, returned pointer, actual LDR and resulting register with the syscall errno. The client-close path does not read errno; the report must label its syscall carry/error separately. Bounded console buffers are observations of attempted output, not proof all bytes were delivered.

Kernel `_psignal` and `_sigexit_locked` observations are function entries, not completed delivery or exit. `_exit1` records the encoded status. Only the actual Thumb STR to `proc+0x128`, followed by the real next instruction with exactly one retired instruction and matching stored value, yields `observed-exit-status-store`. It does not prove process reaping. An intervening interrupt or unexpected call ordering fails the observer conservatively; no completion is inferred across an instruction gap.

`test.log`: 461 ASan/UBSan focused checks, including real interpreter execution of the original BLX, errno LDR and status STR, identity/order/mode/context negatives and unchanged live CPU/RAM/bus reads. Synthetic syscall-return events are not actual OS execution. The linked historical core is not itself sanitizer rebuilt. Another process visiting the same shared-library addresses while our syscall sleeps is explicitly ignored without changing the pending pairing. The new foreign-process regression fails against the preserved 311-check adapter in `before-shared-process-filter/negative.log`; its original source and result remain intact. `ui-test.log`: 20 focused predicate, contact hold/gap, repeated-capture and stage/tail cap checks. Earlier 613 entry-only checks remain separately preserved; they are not added as if one new run.

## Actual scanout and finite touchscreen contract

`stages.json`, `ui-data.h` and `predicate-checks.json` bind eight stages: dismiss Repair, launch Safari, open address field, numeric keyboard, enter numeric loopback URL, load landing, Next, return to landing; then focus the form and observe a bounded diagnostic tail. Contacts use the actual M68 touchscreen device, with 1,080,000 guest timer ticks held and 3,900,000 ticks between presses. No video-time conversion or host/browser surrogate input is used.

Each transition requires two matching actual CLCD scanouts at different guest ticks before advancing. Each stage has both a 1.5B instruction and 180M timer-tick cap. Images are sampled every 2M instructions. The actual native frame17 is the initial alert reference, with its status bar excluded. Other references come from retained genuine 093 browser frames; their 481st-row geometry is handled by dropping exactly the extra top row, without resampling or changing actual scanout. These are bounded readiness predicates with MAE <=2, not claims of future byte-exact native screens. Blank and retained wrong-stage images remain negative controls; URL text has a separate predicate from the numeric keyboard. Failed-form images never serve as successful form templates.

The initial failed zero-instruction preflight is preserved in `preflight-1/`, including its incorrect nearest-row projection. Artifact comparison proved that dropping the first row of the initial browser screenshot produces **all 460,800 native bytes exactly**. Native frame17's selected alert region also matches the loaded scanout exactly. This is an evidenced geometry correction, not a relaxed threshold. The corrected zero-step check is retained separately in `preflight-2/`; `preflight-3/` repeats only loading/bindings/scanout with the final shared-process filter and zero guest instructions.

## Proposed single attempt, pending final review and scheduling

Invocation only after parent review: `python3 .context/guest-http-default/exit-adapter-1/launch.py .context/guest-http-default/exit-adapter-1/run-1`.

The launcher refuses an existing attempt, requires at least 4.5GB available initially, and the runner checks a 4.3GB live floor at scan intervals. It loads the exact checkpoint, binds the original owners/code, and installs the observer. No new boot or image installation is involved. Limits are 8B additional instructions, 450 seconds including initial load, 120 seconds separately for serialization, and 580 seconds for the scoped native process. Normal slices are 1,024 instructions, so the final state may be up to 1,024 instructions after a witnessed stop or instruction cap. Each trace record retains its own exact event instant. The finite form tail is at most 1B instructions and 180M timer ticks, within the overall bounds.

Stop at the first actual committed exit status, original pending-2D hang line, observer/source/order failure, UI stage failure, disk/trace failure, core error or cap. No retry, software fallback, KeepAlive change or cap extension is present. A source/UI failure may stop before the exit cause is found and must remain incomplete. A native interpreter continuation differs from the browser's generated execution, scheduling and autosave and cannot be described as an exact reproduction of the browser session.

Every snapshot is captured only after normal `s5l8900_run` return. No longjmp or fake yielded step is used. Active touch state is preserved rather than changed during cleanup. The serializer writes a `.partial` gzip; the launcher streams the complete decompressed bytes into the existing standard snapshot validator, records raw/gzip size and SHA256, and renames it only after successful full validation. A snapshot is diagnostic evidence, never an automatic app or exit-cause acceptance. All scoped child processes are closed on timeout. The final report keeps function-entry, syscall-return, errno-read and committed-status receipts distinct.

The quiet daemon remains absent in 093's final process list, but its original exit cause is still unknown. This preparation does not create a new milestone or change default-phone integration status.
