# Original Safari serves a real local demo

One disposable native boot and one browser workflow pass. The genuine OS 1.0 Safari app loads a numeric loopback address, follows a link, submits `hi` through a GET form, creates a bookmark, returns Home, and revisits the bookmark. Ordinary interval autosave preserves the page, bookmark and running server; after reload the original app makes two new HTTP requests successfully. This is an **isolated imported phone**, not a feature in the default starting phone yet. No external networking or Weather response is claimed.

## Independently authored service and original APIs

[server.c](server.c), [http.c](http.c) and [http.h](http.h) implement a finite local HTTP daemon using the original libSystem socket APIs. It binds only `127.0.0.1:18081`, accepts only loopback peers, uses fixed buffers, bounds per-request read/write work, and closes each response. The three pages explicitly identify themselves as fixed local demo content. Unsupported paths, methods and malformed requests have explicit responses; there is no filesystem endpoint or host proxy. Qualification stops after 64 connections or 3,600 ordinary listener polls. Those finite lifetime limits must be addressed before a default service is promised.

The [17,516-byte own ARMv6 executable](iphone1-local-http) is SHA-256 `18aff252b132a390881f5d676b44810e979dff8c8384625ae2d62142bf2e5eed`. [Binary/import audit](binary-audit.json) verifies 16 eager original libSystem imports and compatible classic Mach-O load commands. [HTTP tests](http-test.log) pass 12,504 sanitizer assertions; [server ownership/short-I/O/error tests](server-test.log) pass 29,478 assertions. These are host contracts, separately from the actual Safari result. [Historical public ABI receipts](primary-sources.json) and the [086 toolchain/license provenance](../guest-hello/README.md) describe the declarations and linker. No Apple executable is patched or redistributed here.

Only the own executable and launchd plist were added to a clean disposable image. [Installation audit](installed/server.img.json) preserves all 5,178 existing ordinary forks and existing catalog file records; only two parent directory valences increment. Original image SHA remains `87271faa21af0830e2c8d174759f525d25e62adc31bceccaae9acb5230a82e12`; installed image SHA is `fc3f221d3d2552ea517db88ede9f6065bfb2eeb7037102169995591be1e417b9`. ## Actual Safari and persistence evidence

The browser uses the exact [16-file current shell/core/seed projection](site-pins.json), unchanged before and after the run. Setup imports the listener snapshot through the existing hidden diagnostic input; this is explicitly not normal first-visit provisioning. Subsequent input is physical Home and actual canvas touch, including the original numeric keyboard. A read-only Worker message listener retains serial chunks; it does not change guest execution or provide HTTP responses.

The 20 browser checks pass with zero page errors or failed host requests. The [independent parser](audit.py) reconstructs seven complete guest requests/responses, sequential successful send/close results, and loopback peer addresses. The original request identifies `Mobile/1A543a Safari/419.3`. Paths are `/`, `/next`, `/`, `/echo?message=hi`, `/echo?message=hi`, `/`, `/echo?message=hi`; response lengths are **598, 384, 598, 361, 361, 598, 361 bytes**. Every status is 200, every Content-Length is exact, and the host browser makes zero requests to port 18081. The last two requests occur after reload. An interim message incorrectly called the first response 602 bytes; the retained wire and final audit use the correct 598.

No manual Save was invoked. The real 30-second interval advances `savedAt`, and actual reload restores that value before generated execution resumes. Final JIT counters include 626,413,356 retired instructions and 77,194,319 calls, with the phone unpaused. The original bookmark remains in its genuine list after reload and opens the form page again.

Independent PNG decoding verifies exact RGB equality for the saved/restored screen below the status bar (147,520 pixels), the form before/after the workflow (114,560 pixels), and bookmarks before/after reload (147,520 pixels). These are actual **320×481 CSS screenshots**, not rescaled 320×480 buffers. The first artifact auditor had a syntax error, then an incorrect 480-pixel-height assumption; both source/log failures are retained. The corrected audit changes only its image-dimension expectation and passes without a guest retry or pixel tolerance. A prior FIFO test-link failure using the wrong destructor name is also retained; it preceded all guest execution.

## Remaining product boundary

The tested local demo is useful proof of original Safari networking, rendering, forms, bookmarks and saved socket/process state. It does not deliver arbitrary internet access, modify Wi-Fi hardware, or connect the standalone Weather backend. Production assets, browser controls, Apple binaries and saved user phones remain unchanged. A maintainable service, pristine default image, discovery/bookmark flow, lifecycle policy and actual default/offline upgrade regression are the next integration work.
