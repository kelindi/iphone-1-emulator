## Why the first observer was not accepted

Attempt1 printed the same successful exchange, but its native observer required the entire4,848-byte code range at process entry. That range crosses into another virtual page which need not have been faulted in. Because failure details were not captured, this is a source-grounded explanation of the missing entry witness, not a retroactively measured page-table state. The attempt was explicitly terminated after the terminal line, with returncode-15 at64.86seconds; no hidden automatic retry or cap extension occurred.

The corrected observer admits only64 current-page entry bytes, binds the real process and checks full text later at exit. Its [RAM-only peek](observer-v2/peek.c) copies CPU state, flushes only the clone's TLB and walks page tables without any live bus/MMIO access. The existing generic peek helper did not itself flush; its retained-context caller did. This successor makes that private flush explicit. [18 synthetic checks](observer-v2/identity-test.log) reproduce demand-paged admission, deny wrong mode/PC/permissions/code and prove live CPU/TLB/RAM/bus counters unchanged. [20 existing peek checks](observer-v2/peek-test.log) pass; the unflushed helper rejects incorrectly only after another page in an initial broad test, so a tightened single-subpage negative now specifically fails on stale cache acceptance. These failed/insufficient test receipts remain available.

An initial concern that the old observer modified architectural FAR/FSR was corrected after reading `arm_mmu_translate`: it changes TLB/cache counters and caches returned faults, but does not itself write those architectural registers. The corrected observer avoids even those live cache/counter changes. A newline-normalization mistake in the artifact parser is also preserved and fixed without another guest run.
