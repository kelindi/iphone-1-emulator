# Retained guest-work ranking after the 100M correctness gate

The count-only observer passes the actual original machine loop: four complete raw states, original JIT policy counters and the final frame match exactly. Independent retained-byte audit reproduces 73,093,840 generated and 26,906,160 interpreted completed steps, 285,763 interpreter rows, 58,878 reached generated positions and 331,509 merged work keys. There are 2,291 interpreter interrupt entries without a fetched instruction; these remain separate from fetched opcodes. No counts overflowed. [Audit](replay-audit.json), [ranking](hotspot-ranking.json), [exact selected ranges](bounded-loop-ranges.json).

This is the fixed first100M trajectory starting from Home and pressing Settings, **not a separately bracketed warm Settings or Home browser window**. Instruction counts are neither CPU samples nor milliseconds. Mode, opcode, fetched/exception event, status and interpreter-attempt provenance remain available separately in raw rows. The ranking groups only matching virtual instruction identities; no physical address, library name or routine identity has been established. Capstone5.0.7 disassembly describes retained opcode bytes; it does not establish original image/slide binding or dynamic branch edges.

The six-opcode hash-shaped range alone accounts for3.884% of this trajectory, with99.734% generated coverage. Its retained instructions perform `r3 = ip + (lr << 8); lr += r3`, load the next byte with postincrement, compare it with zero, sign-extend it into `ip`, and conditionally branch back. The recurrence is a byte hash shape, not a claimed named hash-table routine. The two arithmetic instructions execute627,761 times each; the four other instructions657,116 each. These counts are not inferred whole-loop credits.

One concrete source-level hypothesis for later testing is a signature-guarded generated-loop specialization in `tools/jit/compiler.cjs`: execute this exact instruction sequence in a tighter bounded WASM loop while preserving every guest retirement, register/flags value, byte load and deadline. Existing coverage is already nearly complete, so adding admission bits would not target its principal cost. This is distinct from parked register omission, guard relocation, region continuation and LTO. It is **not yet justified as a substantial warm-launch optimization**: only3.884% of first100M instructions lie in this range, no time share is known, and V8 may already remove some generated overhead. No candidate is implemented.
