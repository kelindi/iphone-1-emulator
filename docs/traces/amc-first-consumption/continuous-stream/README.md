# Original guest consumes a bounded PCM stream

One isolated Stage U run produces 53 consecutive, real decoded PCM buffers (217,088 bytes), all read by the original guest. The guest completes 51 actual ownership returns; the final two buffers are read but remain owned by the guest at the stop. Every publication matches the independent packetized original-media PCM oracle. Reusing the two hardware buffers requires that the previous generation has complete successful-read coverage, original IPC/acknowledgment, and a verified original owner-store retirement.

The run stops before accepting **AMC+0x400=1**, at PC `c0277ce8`, LR `c0271ac4`, cycle `9874729042`. This is an unsupported BSU control request, not I2S output or an audible-playback result. The preserved original code calls this control from its audio state-saving path. No HAL observation or FIFO request occurs. Actual I2S registers/read/write counters remain zero; the final software ring contains `0x39000` bytes (228 KiB), above its stored `0x38000` threshold (224 KiB), with its reader pointer unchanged. These are actual state observations; the precise intervening userspace threshold branch is not separately observed.

The sixth genuine input request is partly copied: 83,304 bytes total, 17,770 bytes consumed by the decoder, and 65,534 bytes in the owned queue. The sixth capture uniquely matches raw-media offset 81,920, following the first five independently matched spans. The actual copy ledger accounts for every transferred byte, including the partial sixth transfer, and reconstructs the complete final queue. It does not assume ring-buffer continuity or supply oracle data to the engine.
