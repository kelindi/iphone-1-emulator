# Original BSU context source follow-up

This is source analysis after the accepted Stage V stop, not a new guest run or a completed save/restore implementation. The [proposed next contract](next-context-contract.md) records all seven opaque word consumers, the small FIFO, separate SRAM save spans, original power/clock dispatch and reset-before-restore lifetime. Production and snapshot formats remain unchanged.

**Correction:** both original FIFO save and restore loops first branch to a condition block that increments their pointer. Although the body operand uses `+0x18`, the first effective FIFO slot is saved `+0x1c`, following all seven register words. Eight FIFO words end at `+0x38`; count is `+0x3c`. There is no effective seventh-word overlap. [Pinned instruction windows and bounded arithmetic](context-source-audit.json) establish this, including the ninth-word overflow negative. Frozen U/V proposals retain the earlier mistaken overlap concern; this explicit correction supersedes that interpretation.

It establishes clock IDs3/4, power client ID0x10004, and original saved SRAM offsets+28000/16KiB and+14000/32KiB. The extractor is a bounded static byte reader, not a new successful guest read or current-pointer lifetime witness. [Original platform dispatch](platform-gates-dis.txt), [clock control](clock-hardware-dis.txt) and [power control](power-hardware-dis.txt) preserve the source chain.

A key remaining lifetime constraint is original resume `c0276448`: it resets/restarts the engine through `c027628c` before restoring the saved BSU context through `c0271be8`. A coherent functional model needs a separately owned, bounded suspended generation; it cannot silently retain active hardware through reset or destroy the only saved state before restore.
