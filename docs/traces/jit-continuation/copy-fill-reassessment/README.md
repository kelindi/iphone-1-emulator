# Existing-data copy/fill loop check

**No sufficiently strong hot-loop witness is established; no optimization is proposed or implemented.** This is a small source/data reassessment during another agent's quiet window. It uses existing samples and PC counts, with no new guest run or profiling.

The historical software-renderer Settings census records 7,185,147 instructions in the nearest-symbol intervals for kernel/libSystem memcpy/memmove/memset/bcopy/bzero and physical variants, out of557,414,127 recorded instructions: **1.289% of recorded PCs**. This includes user-space memmove/memcpy3,374,975, user-space bzero1,308,392, kernel memcpy/memmove1,158,830 and kernel bzero1,175,949. Aliases at the same address are grouped rather than counted twice. [Full per-interval result](old-pc-counts.json).

**This is not an upper bound on the original600M run.** The preserved bounded-table profiler drops42,561,650 events after32 failed slot probes, about7.1% of requested work. The missing events can belong to any family. It is also an older software-renderer fixture, not current MBX browser work. The retained [source](historical-profile.c) and [log](historical-settings-profile.log) expose those limits. The filtered source PC rows are [retained here](old-selected-pcs.tsv), with hashes of both filtered and full input in the result. The old symbol summary's much larger layer_blit_stack contribution belongs to that software-rendering context and is not presented as current accelerated-app work.

The actual MBX100M region-call census has594,162 calls into entire generated one-KiB regions overlapping these named intervals, of9,273,308 total region calls. These are **region calls, not copy-function calls, loop iterations, bytes copied or instruction counts**; unrelated code can occupy the same region. The accepted browser profile's entire overlapping generated regions account for53.646ms/1.134% first Settings and51.374ms/1.393% warm sampled worker residency. That includes all generated code in those regions. It does not include the unresolved interpreter fallback portion of the same routines and does not establish their total cost. Original generated-module attribution retains the accepted inference limitation; no new debugger bytecode identity is claimed.

[Existing-data mapper](existing.py) parses the real seed export section instead of assuming function-index order, then uses the original region definitions and actual Mach-O text symbols. Exact seed/metadata/guest-image hashes and overlapping intervals appear in [the result](existing.json). Function extents are approximated by the next distinct text symbol, not independently proven symbol sizes; alternate entry aliases are retained. The scripts keep original repository-root artifact paths. No guest binary is newly distributed.

Inline word-copy or fill loops inside other functions remain unresolved: the current MBX data records region calls and first unsupported positions, not complete guest-PC instruction frequency within each function. The older full PC census cannot fill that gap because its workload and missing-event pattern differ. Before a signature-guarded loop proposal, a positive witness would need actual repeated hot PCs/iteration counts in the current workload, original bytes and control flow, and observed source/destination/length patterns. Register/flags, overlapping memory, faults, code aliases and exact instruction/device budgets would still need a full semantic contract. This note establishes none of those prerequisites and does not reopen a parked candidate.
