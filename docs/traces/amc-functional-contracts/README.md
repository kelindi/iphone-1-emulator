# Isolated audio-engine contract tests

This is a native model/test result, **not a new guest run or playback demonstration**. The model is isolated from production and the snapshot format. The accepted genuine-driver boundary remains [milestone070](../../../tweets/070_original_audio_input_captured.md); [milestone072](../../../tweets/072_raw_audio_frame_boundaries.md) proves standalone raw decoding.

The prototype implements real allocated buffers, an owned physical-DMA input queue, device-session configuration, actual decoder consumption and PCM publication, ownership/backpressure, event masks/acknowledgements and bounded quiesce. Its LC/stereo implementation policy is selected by trusted exact program SRAM/write-coverage data. Sample rate comes from the actual session register contract; configuration bytes are generated from those fields. There is no original ASC, packet-table or media-file input in the engine adapter.

The [final report](report.json) records1,615,040 passing checks, mostly per-byte SRAM/write-mask invariants. The [source](source/amc_engine.c) and [test harness](source/test_engine.c) preserve the precise scope. The [current adapter corpus](adapter-audit.json) matches all1,069 original raw frame boundaries and the complete4,374,528-byte PCM control, with no packet sizes or ASC supplied to the adapter. The native engine separately retains the319-byte partial frame at the original16 KiB cutoff;52 additional offline fixture bytes produce frame50 and the correct first49 nonzero PCM publications.

The independently constructed [SRAM/mask audit](mask-audit.json) verifies the complete result, including200,704 actual published PCM bytes and172,012 original bytes unchanged outside the union of three explicit write masks. Initialization writes12 bytes, PCM/count/ownership writes8,200 bytes, and simulated original host release/session writes12 bytes. This audit imports no engine helper. Original media, SRAM/program bytes and decoded audio stay in the isolated workspace; this directory retains source, logs, records and hashes only.

Root review found and corrected two real admission defects: active DMA disable/restaging was falsely acknowledged, and idempotent ownership-release writes were rejected. The [retained correction record](review-corrections.md) also covers the guarded power/clock boundary and event preservation on terminal diagnostic failures. All pass in the final run. Existing valid input completion remains pending even if decoding later stops; a decoder error is not an invented hardware reset.

The original output handler calls service before its trailing event acknowledgement. The deliberately broken [synchronous-service variant](synchronous-service-mutant.c) publishes too early and [fails immediately](synchronous-mutant.log). The real engine queues work and holds the next publication until the previous event is acknowledged.

Exact commands and local process timings are in [commands.json](commands.json); they are not performance benchmarks. Native tests have256 MiB address-space,120-second CPU and180-second wall limits. The input queue is64 KiB, each step copies at most4 KiB and decodes at most one access unit. Upstream FAAD source/build/license provenance remains in [the072 bundle](../aac-framing/provenance.json); no production dependency has been adopted.

All earlier frozen sources, actual binary/audio/SRAM/mask captures and test failures remain under `.context/amc-first/stage-f/`. Final source/tests must be reviewed before the next genuine resource/configuration and first-PCM-publication run. Unsupported active power transitions, BSU state, other codecs, session flush and serialization remain explicit stop boundaries. I2S/speaker consumption and audible playback are still unimplemented.
