# Isolated connected-cluster generator

No production edits or guest runs by this subtask. `generator.cjs` exports `generate(regions, offsets, options)` for arbitrary synthetic region arrays and the exact retained production input. Regions accept Map or pair-array `ops`. Options allow `maxCluster` 1–4 and explicit `clusters` of original indexes for boundary tests. `build-seed.cjs` generates the retained 512-region module into `seed/`; this adds no coverage.

The default deterministic graph reads constant r15 assignments from exact original emitter output, links their destination pages to existing region entries, and greedily groups connected nodes in source order, maximum four. This graph is a conservative static candidate graph, not measured transitions: same-page alternate ISA candidates may be grouped and dynamic branches can execute within a cluster if their actual target matches, but dynamic destinations are not inferred as static edges. This first implementation does not rank edges by measured frequency.

Balanced WAT expression extraction retains each original complete run block, including internal dispatch, raw guards, span checks, instruction bodies, budgets and counters. Only the region exit label changes (`$done` to `$region_done`). The original CPU-register/flags/fetch initialization runs once, and the original spill epilogue runs once. Singletons remain byte-identical original function WAT. Connected regions preserve all 16 register locals and CPSR flags between members. `$why` is explicitly reset to zero at each member entry because some original refusal paths exit without assigning it; this restores the original per-function local default and prevents stale reason2/3 from retriggering continuation.

After a member returns, continuation is permitted only for original page/mode reasons2/3, positive generated count, and remaining instruction budget. The selector checks member page, ISA and alignment before calling `env.connected_fetch(c, pc, flags)`. Unknown cluster destinations and exhausted budgets do not call the helper. Admission, installed/disabled state, IRQ/fault checks and nonwalking fetch refill are the helper's contract, owned by root; rejected admission is not a successful fetch. Initial entries use the runtime's already validated fetch and do not call this helper. All other exits terminate globally. A selected destination that refuses without progress exits; it does not retry.

Stale callback arguments come from the actual member whose raw guard failed. Each original export is a DISTINCT tiny WASM wrapper calling its shared internal cluster. Export aliases were rejected because Emscripten addFunction deduplicates identical function objects, violating per-region retirement/table ownership. Wrapper cost is retained in any future benchmark; inlining is not assumed.

`generator-test.cjs` reports32 assertions: original block projection, actual WASM assembly/execution, register/count continuity, exact/zero budgets, unknown source/target, fetch refusal, ARM-to-Thumb transition, page fallthrough, destination ARM/Thumb stale identity, span refusal, VFP refusal after a positive source prefix, definitions equality, distinct exported function identity, graph formation and invalid-cluster rejection. These do not replace root's actual CPU/MMU/lifecycle oracle. Initial expanded test used unsupported Thumb BX0x4708 and failed with `empty region`; the test was removed rather than extending original opcode coverage. ARM BX→Thumb is supported and tested. The initial eight-case test/build preceded the discovered reason-reset correction and is not the final qualification.

Final output hashes/counts are in `seed/build-report.json`; source pins in `generator-pins.json`. No performance claim. Root owns actual C helper, exact CPU/MMU boundary tests and replay qualification.
