All bytes are fixed/bounded (overall<=300000); no raw C structs or padding.

Every non-host `s5l_mtz1_t` field is included: all power/select/protocol/attention flags; operating_mode/seq/last_n; params49; actual rx1024; pkt_len/rx_len/checksums; all protocol/byte/frame counters; complete geometry; pending payload/length; each field of all5 last_contacts and all5 held contacts; frame sequence/time; held_n/lift_pending/tick_acc; uptime_ms and uptime_tick_acc. Only trace is host diagnostic policy and remains the fresh caller's value. An independent header inventory must prove coverage, including nested geometry/contact arrays. Sidecar decoding validates booleans, actual array lengths, contact counts, pending bounds, frame/uptime fractional bounds and receive-overflow representation before assigning any output.

## Transactional integration sequence

1. Verify manifest/version/whole file bounds/hash against immutable bytes. Decode/check the outer checksum and both device records into temporary allocations; retain callbacks/trace policy.
2. Construct a fresh M68 and bind all bus/DMA/GPIO/SPI callbacks before assigning restored state. Apply original v39 snapshot through the standard transactional loader.
3. Assign the fully validated SDIO and Z1 records, retaining host callback/trace ownership. This supplies actual previously omitted bytes; it does not infer missing v1 data. Cross-check machine instant/board/IRQ.
4. Re-save this fresh machine and complete v2 sidecar and require exact raw input equality before returning the new phone. This binds every duplicated standard-Z1 field to the immutable machine bytes and prevents inconsistent sidecar overrides. Any failure frees the new phone; the original remains untouched. No comparator exclusion is added for Z1.
5. Synthetic original-in-memory versus fresh v2 tests must cover midpacket byte response, deselection/finish, ordinary next select, C2-prefix select retention, overflow, pending/held touch reports and nonzero uptime/timestamp/velocity continuation. Each whole Z1 field and canonical device/machine bytes must match. Negatives include old-v1 rejection, checksum/version/length corruption, rehashed invalid booleans/bounds/contacts/time and conflicting duplicated standard fields; preserve a v1 negative that fails the actual8-byte receive-state case.
