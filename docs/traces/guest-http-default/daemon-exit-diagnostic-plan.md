# Proposed daemon-exit diagnostic — not executed

The retained final state proves absence of PID21, but neither timing nor cause. A new crashdump-process crash cannot be attributed to the daemon. Do not change KeepAlive, logging mode, executable bytes, service policy, graphics mode, or inject a response to make a rerun succeed.

The shortest next causal experiment is an isolated native continuation from the exact retained listener/Home checkpoint, with the same quiet executable and image. It must observe process lifecycle before the relevant Safari interaction, not start from the final snapshot after the daemon is already gone. Parent scheduling/review and a separately frozen bounded run are required; no diagnostic is launched by this document.

1. First use artifact-only source/symbol qualification to bind the actual kernel's exit/signal path and the exact own executable/import relocation addresses. Record original executable SHA, ARM/USR entry/code windows, PID/task, TTBR and real return context. Do not infer kernel offsets from another OS version or mutate CPU state to make reads succeed.
2. Observe only our process: real calls/returns for `_exit`, listener poll/accept/client close, console write and actual errno; plus its original kernel exit status and fatal signal delivery if source-grounded. Retain a bounded ring with sequence numbers and overflow refusal. Record attempted logging bytes and returned byte counts to distinguish an ordinary error from lost console output. Quiet socket data need only lengths/status/hashes; this is not a verbose replacement binary.
3. Observe process presence at exact bounded instruction prefixes, retaining the last live and first absent prefix. If the kernel/USR hooks cannot bind the real process safely, stop as an observer failure; never interpret unavailable reads as zero exit status. Capture source/code witnesses before decoding values.
4. Reproduce only the existing original-Safari path through landing page, Next and first form, within one fixed continuation budget no larger than the prior 900-second browser cap and an explicit instruction limit derived before execution. Stop at the first witnessed daemon exit, first unbound observer boundary, or cap. Preserve a normal outside-run snapshot and the last trace even if no cause is captured. No automatic retry or cap extension.
5. If original graphics stalls first while the daemon remains alive, record the separation. A renderer correction needs its own reviewed candidate and differential acceptance; it must not silently change this daemon baseline. Parent may instead select a browser-level process observer once a safe read-only export path is qualified; do not add a production diagnostic API merely for this plan.

Acceptance is an actual bound exit/signal/error-return witness with original process identity and ordering, or an explicitly incomplete result. OOM, SIGPIPE, deliberate loop exhaustion and crash are hypotheses until a witness establishes them. Current source has no healthy lifetime cap, sets SO_NOSIGPIPE, and leaves failed-request handling inside the persistent loop. No new own-binary safety patch is justified yet.
