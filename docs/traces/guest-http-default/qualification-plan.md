## One original Safari session on the final executable

Use a fresh private profile and a pinned projection of the latest web UI,
worker, core, loader, seed and assets. Do not alter production. Use existing
hidden import/export controls only as explicitly recorded fixture transport;
all guest actions use genuine touch/Home input. Require positive generated CPU

Bound the single session to **900 seconds**, including adaptive real keyboard
coordinates and settling. Record the complete original-speed screen video,

Do not restart the browser or repeat the native boot on failure.

The ordered acceptance is:

1. Verify Home, Settings and Contacts render from the pristine phone. Preserve
   its current application data. Return Home normally.
2. Open original Safari and type `127.0.0.1:18081` using its original keyboard.
   Require the visibly labeled local landing page. Follow its Next link and
   return through its Home link.
3. Enter a short newly chosen form token through the genuine keyboard. Require
   the exact token in the generated local form result. The actual token and
   input steps are recorded, not injected into guest memory.
4. Navigate to `/`, create **Local demo** through the genuine bookmark UI, and
   retain the other existing bookmarks. Return Home, reopen Safari, and use
   this bookmark to render the landing page.
5. Wait for actual ordinary interval autosave to advance savedAt; reload and
   require that exact saved record. Use the bookmark again, submit a different
   short token and require its new rendered value. The response policy is
   no-store, and the new token distinguishes restored pixels from a newly
   processed form. Require unpaused positive JIT after reload.
6. Finish at genuine Home. A separately labeled diagnostic export captures the
   matching starting state, with enabled-wait and download/error receipts. This
   does not substitute for the already-required real autosave. Extract and
   compare retained application files against the pristine source: only the
