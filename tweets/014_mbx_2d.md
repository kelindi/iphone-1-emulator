## Tweet idea

> The app-close animation now works because we reverse-engineered how OS 1.0 pads MBX 2D blit packets. Apple drivers were submitting packets the emulator previously discarded.

## What you're seeing

Screen recording: `videos/browser_home_settings_safari_cpi1.mp4` (0:20–0:29)

Safari opens, then Escape is pressed and the 3D-animated app-close returns to the genuine home screen. Earlier this was a black frame because the 2D blit parser rejected the packet.

## ELI5 technical explanation

- **MBX** is the PowerVR 2D/3D graphics accelerator in the S5L8900. The kernel driver builds command rings in RAM and writes them to the MBX MMIO range.
- A 2D packet has a body followed by one or more `0x70000000` terminator words. Later iOS always pads to the maximum terminator count; iPhone OS 1.0 uses a **variable** count.
- The old parser expected the maximum padding and so mis-sized every OS 1.0 blit. It also rejected "constant-u" textured sprites (where `u_start == u_end`) that the app-close animation uses to stretch a single column texture.
- We made the parser stop at the first terminator, consume the contiguous run, advance by the real length, and accept constant-u. The close transition now returns to SpringBoard instead of hanging on a black screen.

## Why it matters

Graphics is the path between the real apps and the screen. If packet parsing is off by even one word, the whole UI freezes or renders garbage.
