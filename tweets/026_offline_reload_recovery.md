## Tweet idea

The 2007 iPhone now survives going offline in a very modern way: download it once, disconnect the browser, and reload the real OS. We also deliberately corrupted a cached firmware file—then watched it reject the bad bytes and recover after reconnecting.

## What you're seeing

Recording: [offline_reload_recovery.mp4](videos/offline_reload_recovery.mp4), with [thumbnail](thumbnails/offline_reload_recovery.jpg).

The complete automated Chrome run shows initial startup and Keep offline (0–6.5 seconds), a reload with browser networking disabled (6.5–9.3 seconds), visible startup failure after deliberate cache corruption (11.7 seconds), and successful Retry after reconnecting (15 seconds). The network disconnect is applied by Playwright; it is not a guest Wi-Fi feature or an on-screen simulation. The matching test report is generated by `npm run test:offline -- --record`.

## ELI5 technical explanation

Saving the running phone and saving the website are separate jobs. IndexedDB keeps the user's machine checkpoint. Cache Storage keeps verified firmware, while an optional service worker keeps the small website and WebAssembly program needed to open it without a connection.

The build computes a content hash for the complete website bundle. Installation verifies every file against that bundle and discards incomplete installations; an update waits until the old phone's tabs close, so a running emulator does not suddenly receive a mismatched program. Firmware parts have their own SHA-256 checks before caching or decompression. A corrupt cached part is deleted and downloaded again once. Without a connection this fails visibly, leaving Retry available.

Six real-browser checks passed, including a disconnected reload, rejection/removal of a corrupted firmware cache entry, and reconnect/retry. Four firmware helper tests cover cache repair, corrupt network data, multipart gzip, and origin checks; four checkpoint codec tests also pass. Browser storage can still be cleared, so Export remains the durable backup option.

## Why it matters

The phone can reopen independently of a live connection after the user chooses Keep offline. Downloads now have an explicit integrity and recovery path, providing a more dependable foundation for the working offline apps. Guest internet access and legacy app services remain separate unfinished work.
